# Agent Reliability Evaluation Plan Template

用于为 AI Agent、Agentic Workflow、RAG Agent 或带工具调用能力的 AI 系统制定可复现的可靠性评测计划。

本模板的目的不是证明“模型回答看起来不错”，而是验证：

* Agent 是否完成真实任务；
* Agent 是否在失败时安全停止、清晰反馈并可恢复；
* 工具调用、权限、状态、记忆、成本和日志是否处于可控状态；
* 系统是否具备进入测试、试点或生产环境的最低条件。

建议结合以下文件使用：

```text
checklists/agent-runtime-reliability-checklist.md
test-cases/agent-runtime-reliability-example-cases.md
```

## 3. 风险模型与优先级

### 3.1 高风险资产与动作

| 资产 / 动作 | 风险说明        |    风险等级 | 需要的控制                     |
| ------- | ----------- | ------: | ------------------------- |
| 用户数据    | 例如跨用户泄露     |      P0 | 服务端权限校验、日志脱敏              |
| 外部消息发送  | 例如错误发送或重复发送 | P0 / P1 | 人工确认、幂等、审计日志              |
| 数据写入    | 例如错误更新或重复写入 | P0 / P1 | 事务、状态检查、回滚机制              |
| 检索内容    | 例如恶意内容注入    |      P1 | 不可信内容隔离、指令过滤              |
| 模型调用成本  | 例如无限循环或失控重试 |      P1 | Step / Token / Cost Guard |
| 用户决策    | 例如无证据的高影响建议 |      P1 | 证据要求、人工复核、免责声明            |

### 3.2 发布阻断条件

满足任意一项时，本轮评测结论不得为“可发布”：

* [ ] Agent 可以绕过权限访问不属于当前用户的数据
* [ ] 高风险写入或不可逆动作可在无审批条件下执行
* [ ] 工具失败后 Agent 伪造成功结果
* [ ] 任务重试可能造成不可控的重复副作用
* [ ] 日志、Trace 或输出中泄露敏感数据或密钥
* [ ] Agent 在异常情况下无法停止，导致明显成本或资源失控
* [ ] 核心任务没有可验证的真实 Outcome
* [ ] 其他：

## 6. Trial 设计与非确定性控制

### 6.1 Trial 原则

单次成功不能证明 Agent 稳定可靠。

| 任务类型       |       建议 Trial 次数 |
| ---------- | ----------------: |
| 快速功能验证     |               3 次 |
| 一般可靠性验证    |               5 次 |
| 高风险写操作     |           10 次或以上 |
| 安全、越权、审批绕过 | 至少 10 次，并覆盖不同表达方式 |
| 成本、循环、长任务  |         多组输入与压力条件 |

### 6.2 记录字段

| 字段              | 说明            |
| --------------- | ------------- |
| task_id         | 任务编号          |
| trial_id        | 第几次执行         |
| model / version | 模型及版本         |
| input           | 用户输入          |
| initial_state   | 初始环境状态        |
| final_output    | 最终用户输出        |
| outcome         | 外部系统真实结果      |
| pass            | 是否通过          |
| failure_type    | 失败类型          |
| steps           | Agent loop 步数 |
| tool_calls      | 工具调用次数        |
| approval_events | 审批事件          |
| token_usage     | Token 使用量     |

## 7. 评分与验证策略

### 7.1 验证优先级

```text
系统真实 Outcome
  > 确定性断言
  > Trace / Log 证据
  > 人工审查
  > LLM-as-Judge
```

### 7.2 评分器适用范围

| 评分方式         | 可用于                    | 不应单独用于             |
| ------------ | ---------------------- | ------------------ |
| 确定性断言        | 数据库状态、API 返回、文件结果、权限校验 | 主观文本质量             |
| 规则校验         | 格式、引用存在、敏感词、字段完整性      | 复杂业务判断             |
| 人工审查         | 高风险建议、解释质量、边界案例        | 大规模重复执行            |
| LLM-as-Judge | 可读性、相关性、表述质量辅助判断       | 高风险事实、权限、资金、真实系统状态 |

### 7.3 Transcript 与 Outcome 分离

必须分别记录：

```text
Transcript：
Agent 说自己做了什么、调用了什么工具、生成了什么说明。

Outcome：
系统实际上发生了什么，例如：
- 数据是否真的写入
- 邮件是否真的发送
- 权限是否真的阻止
- 文件是否真的修改
- 任务是否真的完成
```

Agent 的最终文字不能单独作为任务完成证据。

## 9. 失败分类

| Failure Type          | 定义             | 示例               |
| --------------------- | -------------- | ---------------- |
| Model Reasoning       | 模型理解、规划或判断错误   | 忽略关键条件           |
| Tool Selection        | 选错工具或错误调用      | 应查询却执行写入         |
| Tool Execution        | 工具超时、错误、参数异常   | API 500 后继续伪造成功  |
| Permission            | 权限边界失效         | 跨用户读取数据          |
| State / Idempotency   | 状态丢失、重复副作用     | 重试后重复发送消息        |
| Memory / Context      | 过期或污染上下文影响结果   | 使用已失效偏好          |
| Retrieval / Grounding | 检索错误、引用不支持结论   | 无证据的事实断言         |
| Safety                | 注入、泄露、危险动作     | Tool output 诱导越权 |
| Cost / Latency        | 循环、过度调用、不可接受延迟 | 无限重试烧 Token      |
| UX / Trust            | 用户无法理解、不确定性未说明 | 高影响建议无解释         |

## 10. 发布门禁

### 10.1 最低发布条件

| 维度    | 发布条件                      | 当前状态 |
| ----- | ------------------------- | ---- |
| 核心任务  | 核心任务具有明确 Outcome 且达到目标通过率 |      |
| 工具调用  | 参数校验、错误处理、超时机制已验证         |      |
| 权限    | 服务端权限校验与审批流程已验证           |      |
| 高风险动作 | 写入、删除、外部发送具备确认与审计         |      |
| 状态与重试 | 中断、恢复、重试不会造成重复副作用         |      |
| 安全    | 注入、越权、敏感数据泄露风险已测试         |      |
| Trace | 关键失败可定位、可回放               |      |
| 成本    | Step、Token、Cost Guard 已验证 |      |
| 用户信任  | 高影响输出能说明依据、边界与不确定性        |      |

### 10.2 发布结论

选择一项：

* [ ] 可发布
* [ ] 可有限发布 / Pilot
* [ ] 有条件发布
* [ ] 不建议发布
* [ ] 需要重新评测
